> 2026-11-09 개정: 주 트랙을 A(개장 전 → 당일 종가)로 변경. B 트랙 폴더는 그대로 보관한다.
> 스키마·코드는 A·B 모두 지원하도록 전환 완료 (`05_실행구조.md` "A 트랙 운영").

스키마 파일: `06_코드/schemas/` · 설정: `06_코드/experiment_config.json`

## 폴더 구조

트랙별로 하위 폴더(`A/`, `B/`)를 둔다. 이하 `<T>`는 트랙.

| 폴더 | 내용 | 파일 규칙 |
|---|---|---|
| `01_리서치_원본/` | 입수한 PDF 원본 (트랙 공용) | `YYYY-MM-DD/` 아래에 다올·유진 PDF |
| `02_시장데이터/스냅샷/<T>/` | 예측 시점 입력값: 전일 종가 + 미국 세션 + 리포트 입수 시각 | `YYYY-MM-DD.json` |
| `02_시장데이터/정답/<T>/` | 당일 종가 | `YYYY-MM-DD.json` |
| `02_시장데이터/리포트방향/<T>/` | 리포트 방향 전망 수동 태깅 (기준선용, 장 마감 전 작성) | `YYYY-MM-DD.json` |
| `04_예측결과/<T>/` | AI 예측. 저장 후 수정 금지. 지연분은 `late/` | `YYYY-MM-DD.json` |
| `05_평가결과/<T>/` | 수치 평가(`날짜.json`), 근거 채점(`rationale/`), 시험(`dryrun/`) | |
| `06_코드/` | 스키마, 설정, 실행·평가 코드, 프롬프트 | |
| `99_로그/` | 실행 로그(`runs/`), 요약(`runs.log.jsonl`), 시험(`dryrun/`) | |

입력 패키지는 프로젝트 안에 두지 않고, 실행 시 프로젝트 밖 임시 폴더에 만들어 그곳에서 예측 세션을 실행한다.

## 하루 흐름 (거래일 D)

```text
D-1 15:45~  D-1 종가 기록 → 02_시장데이터/정답/A/<D-1>.json   (= 다음 날 스냅샷의 전일 종가)
D   ~08:30  다올·유진 D일자 PDF 다운로드 → 01_리서치_원본/<D>/   (워터마크 시각 ≤ 08:45)
            미국 세션(S&P·Nasdaq 등락률, UST10Y 변화) 입력 → 스냅샷 02_시장데이터/스냅샷/A/<D>.json
            예측 실행 → 04_예측결과/A/<D>.json
D   08:45   컷오프 (국채선물 개장)
D   장중    리포트 방향 태깅 → 02_시장데이터/리포트방향/A/<D>.json
D   15:45~  D 종가 기록 → 02_시장데이터/정답/A/<D>.json
            수치 평가 → 05_평가결과/A/<D>.json
            근거 채점 → 05_평가결과/A/rationale/<D>.json
```

정답 파일 하나가 그날의 정답이자 다음 거래일의 전일 종가 역할을 한다. 그래서 하루에 사람이 넣는 값은 **아침 미국 값 3개 + 마감 종가 4개**뿐이다.

## 필드 규칙

- **방향은 선물 가격 기준.** 상승 = 금리 하락 = Long Duration. `duration_view`는 up→long, down→short, neutral→neutral과 일치해야 한다.
- **파생값은 저장하지 않고 평가 단계에서 계산:** 일간 변화 = `D 정답 close` − `D-1 정답 close`(스냅샷의 `prev_close`). 틱 = 변화 ÷ `tick_size`.
- **시각은 모두 KST(+09:00)**, 초 단위까지 기록.
- 스냅샷에는 값을 **기록한 시각(captured_at)** 과 **리포트 입수 시각(obtained_at, 워터마크)** 을 넣어 `late` 판정과 누수 검증의 근거로 쓴다.
- `input_manifest_sha256`: 입력 패키지의 파일 목록과 해시. 사후에 입력이 바뀌지 않았음을 증명한다.
- 월물: 스냅샷과 정답에 국채선물 월물(예: `2612`)을 함께 기록한다.

## 구현 시 검증할 규칙 (스키마로 표현 불가)

1. 확률 합계 = 1 (허용 오차 0.01)
2. `direction`이 `prob`의 최댓값과 일치
3. `duration_view`가 `direction`과 일치
4. `executed_at` ≤ 컷오프(08:45) → 초과 시 `late`
5. 리포트 `obtained_at`이 컷오프 이후면 해당 리포트는 입력 불가 → `late`
6. `executed_at` ≥ `captured_at`, 정답 `recorded_at` > 예측 `executed_at`
7. 같은 날짜의 예측 파일이 이미 있으면 덮어쓰기 거부
8. 스냅샷 `prev_close`와 직전 정답 파일 값 일치, 월물 일치
9. 가격·전일 종가는 스냅샷을 정본으로 사용. 리포트 간 수치 불일치는 프롬프트에서 출처를 명시하게 함
