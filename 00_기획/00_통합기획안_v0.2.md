# 통합 기획안 v0.2 — 오전 매크로 정보 기반 국내시장 잔여장 방향 예측

> 상태: 초안. 첫 기획안(멘토) + 수정 기획안 + 기존 `01`·`02` 문서를 합치고, 샘플 PDF 점검에서 나온 문제를 반영함.
> `[결정필요]` 표시는 사용자 확정 전까지 잠정값.

---

## 0. 세 문서의 관계

| 항목 | 첫 기획안 (멘토) | 수정 기획안 | 이 문서(v0.2) |
|---|---|---|---|
| 예측 대상 | 다음날 시장 반응 | 09:30 → 당일 장 마감 | **T 시각 → 장 마감** (T는 §2에서 재설정) |
| 입력 | 데일리 리서치 + 전일 종가 | 리포트 2종 + 미국 지수 + 09:30 스냅샷 | 동일 (스냅샷 시각만 변경) |
| 평가 | LLM이 평가 | 수치 평가 위주 (LLM 평가 빠짐) | **수치 평가 + LLM 근거 평가 병행** |
| 개선 루프 | 결과 보고 개선 | V1→V2 | 유지, 한 번에 한 요소씩 |
| 실행 | Claude Code 토큰 사용 | Claude Code 실행 | 동일 + 격리 실행 조건 추가 |

수정 기획안에서 **예측 대상이 "다음날"에서 "당일 잔여장"으로 바뀌었다.** 의도된 변경이면 멘토에게 한 줄로 알려서 합의할 것.

## 1. 핵심 질문

> 오전에 확보 가능한 리포트·시장정보만으로, AI가 당일 잔여장의 채권 방향을 **단순 기준선보다 낫게** 맞히는가? 그리고 그 근거는 타당한가?

초기에는 거래 없이 모의 신호만 기록한다.

### 트랙 구성 (사용자 결정)

| 트랙 | 시각 | 입력 | 예측 대상 | 상태 |
|---|---|---|---|---|
| **B (주 트랙)** | 오전 T=10:00 | 당일 아침 리포트 + 미국 야간 + 오전 스냅샷 | T → 당일 마감 (잔여장) | 지금 진행 |
| A (추가 트랙) | 장마감 후 | 마감 후 리포트(미정) + 당일 국내 마감 | 다음 거래일 | B 안정화 후 추가 |

- A 트랙의 전제: 장마감 후 나오는 리포트 선정. 다올·유진은 아침 리포트라 A 트랙 입력으로 부적합하다 `[확인필요]`.
- A는 미국 야간장이 미반영 상태라는 구조적 약점이 있다. 추가 시 같은 10:00→마감 구간에서 A와 B를 비교해 "오전 정보 추가의 가치"를 측정한다.
- 입력 양식·JSON 스키마·평가 코드는 두 트랙이 공유하도록 설계한다(트랙 필드로 구분).

## 2. 점검에서 발견된 문제 (우선순위순)

### ① 09:30 컷오프를 리포트 입수 시각이 충족하지 못함 (실측)

2026-11-05 샘플 PDF의 생성·저장 시각:

| 자료 | PDF 생성 시각 | 파일 저장 시각 |
|---|---|---|
| 다올 Daily Bond Morning Brief | 09:27:22 | 09:57 |
| 유진 FICC Update | **09:50:46** | 10:08 |

- 유진 리포트는 생성부터 09:30 이후라서, 기획의 누수 방지 규칙(`01_리서치_선정.md`: 장 시작 이후 생성된 리포트는 같은 날 입력으로 쓰지 않음)을 **그대로 적용하면 정식 표본에서 탈락**한다.
- 생성 시각이 곧 게시 시각은 아니므로 **1일치 표본일 뿐**이다. 다만 두 리포트 모두 실제로 손에 쥐는 시각이 10시 전후다.
- **확정(사용자 결정): T = 10:00.** 잔여장(10:00→15:45)이 장중 대부분을 차지한다.
- **주의:** 유진 생성(09:50) 뒤 여유가 10분뿐이고, 샘플 일의 실제 저장 시각(10:08)은 이미 T를 넘었다. 입수가 늦은 날은 `late`로 분리된다. 첫 5거래일의 입수 시각을 기록해 `late` 비율이 높으면 T를 재검토한다.

### ② 운영 방식과 기준 시각이 서로 모순

`02` 문서에 "데일리 업무 종료 후 입력하고 즉시 예측 실행"과 "기준 시각 09:30"이 같이 있다. 퇴근 후 입력하면 T 시점 스냅샷은 사후에 재구성한 값이 된다.
- **제안:** T 시각에 스냅샷을 직접 기록하고 그 자리에서 예측을 실행한다. 늦게 실행하면 `late` 상태로 분리하고 정식 성과에서 제외한다(`02`의 지연 실행 규칙 유지).

### ③ 20거래일은 성능 판정에 쓸 수 없는 표본

- 적중률 60%라 해도 n=20이면 95% 신뢰구간이 대략 ±22%p. 50%와 구분되지 않는다.
- 참 적중률 60%를 50%와 구분하려면(검정력 80%, 단측 5%) 대략 **150일** 필요하고, 중립 예측을 제외하면 더 늘어난다.
- **제안:** 20일은 "파이프라인이 끝까지 돌아가는지" 확인하는 **시험 운영**으로 규정한다. 성능 결론은 내지 않는다.
- 소급 검증(백필)은 사용 모델의 지식 컷오프 **이후** 날짜만 쓰면 모델 기억 오염 없이 표본을 빠르게 늘릴 수 있다. 단 과거 T 시각 스냅샷이 필요하므로 **분봉 데이터 접근 가능 여부**가 관건이다 `[결정필요]`.

### ④ 평가 지표가 너무 많아 우연히 좋아 보일 수 있음

타깃 4개 × (방향·확률·틱·판단) × 모의손익이 전부 평가 대상이면, 표본이 작을 때 어느 하나는 좋게 나온다.
- **제안:** **주 지표를 사전에 하나로 고정**한다. 보조 타깃은 기술 통계로만 보고한다(§5).

### ⑤ "중립"과 확률 임계값이 정의되지 않음

- 중립 구간(예: |Δ| ≤ N틱)이 없으면 방향 적중이 계산되지 않는다. 시작 전에 N을 고정한다. 기준은 과거 동일 구간 변동폭 분포(예: 중앙값의 절반) `[결정필요]`.
- 모의 매매의 "확률 60%"도 임의값이다. LLM의 확률 출력은 보정이 잘 안 되는 경우가 많고 20일로는 검증이 불가능하므로, **V1은 확률을 기록만 하고 매매 규칙은 방향 + 확신도 3단계(상/중/하)**로 단순화한다.

### ⑥ PDF 텍스트 추출은 신뢰하기 어려움

다올 PDF를 텍스트로 뽑으면 표의 라벨과 숫자가 분리·뒤섞인다(Excel 출력물). 유진도 표가 많다.
- **제안:** 텍스트 추출 대신 **PDF 원본을 Claude에 직접 읽히는 방식**을 기본으로 하고, 핵심 숫자(국채선물 1D 등)만 사람이 대조 검증한다.

### ⑦ AI가 애널리스트 전망을 베끼는지 구분 필요

유진 리포트는 해석·전망을 포함한다. AI 성능이 아니라 애널리스트 성능을 재는 셈일 수 있다.
- **제안:** 기준선에 "리포트의 방향 전망을 그대로 따름"을 추가한다(방향은 최초 1회 수동 태깅).

### ⑧ 평가 오염 경로 (실행 환경)

- 정답 파일이 예측 실행 폴더에 있으면 AI가 읽을 수 있다 → **정답은 별도 폴더**, 예측 세션에는 당일 입력 파일만 제공.
- 전역 CLAUDE.md·OMC 훅·메모리가 예측 세션에 로드되면 프롬프트가 날마다 달라지고 과거 결과가 새어 들 수 있다 → **매일 새 세션, 컨텍스트 격리**. 구체 방법은 구현 단계에서 확인한다.
- 모델 ID를 매 실행 기록한다(모델이 바뀌면 버전이 바뀐 것).

## 3. 일별 데이터 구조 (한 거래일 = 한 행)

```text
[메타]    date, t_scheduled, t_executed, status(ok / late / missing),
          model_id, prompt_version, report_available_at(다올, 유진)
[입력]    다올 PDF, 유진 PDF, S&P500·Nasdaq 종가/등락률(선택: Dow, VIX),
          T시각: 3Y·10Y 국채선물, KOSPI200, USD/KRW 현재값과 전일 대비
[예측]    JSON (§4) — 저장 후 수정 불가
[정답]    장 마감값 (별도 폴더, 예측 후에만 기록)
[평가]    자동 계산값 + LLM 근거 평가
```

## 4. AI 출력 (JSON, 주 타깃 = 10년 국채선물)

```text
direction            up / neutral / down
prob_up/neutral/down 합계 100%
expected_ticks       T → 마감 예상 변동(틱)
confidence           high / mid / low   ← V1 매매 규칙은 이 값을 사용
duration_view        long / neutral / short   (direction과 일치해야 하며 불일치 시 오류 처리)
sub_targets          3Y 방향·틱, KOSPI200 수익률, USD/KRW 변화
rationale            상승 요인 / 하락 요인 / 이미 반영된 요인 / 무효화 조건 / 확신 낮은 이유
```

## 5. 평가

**주 지표(사전 고정):** 10년 선물, 비중립 예측의 **방향 적중률**과 **신호당 평균 획득 틱**을 기준선과 비교.

**보조(기술 통계만):** 틱 오차, 3Y·KOSPI200·USD/KRW 적중, 확신도별 적중률, 확률 보정(표본 충분 시), 모의 손익·비용 차감·최대 연속 실패·신호 빈도.

**LLM 근거 평가(멘토 요청 반영):** 장 마감 후 **예측과 별개의 세션**이 근거·무효화 조건·"이미 반영" 판단이 실제 움직임과 부합했는지를 채점한다. 예측 세션은 정답을 보지 못하고, 평가 세션만 정답을 본다.

**기준선:**
1. T까지의 움직임이 마감까지 지속
2. T까지의 움직임이 반전
3. 항상 중립
4. 리포트 방향 전망 추종
5. 같은 입력에서 AI 예측 날짜를 섞은 무작위 대조(순열 검정, 표본 충분 시)
6. AI 예측

미국 10년 금리 단독 기준선은 T 시점엔 이미 반영된 정보라 잔여장 예측력 비교로 부적합하다. 삭제하거나 참고용으로만 둔다.

## 6. 누수 방지 체크리스트

- [ ] T 이후 생성·게시된 자료는 입력 불가 (생성 시각을 파일별 기록)
- [ ] 예측 JSON 저장 후 수정 금지, 실행 시각 기록
- [ ] 정답은 별도 폴더, 예측 세션에서 접근 불가
- [ ] 매일 새 세션, 전역 설정·메모리 미로드
- [ ] 프롬프트 변경 시 버전 부여, 모델 ID 기록
- [ ] 백필 시 사용 모델 지식 컷오프 이후 날짜만 사용
- [ ] 국내 종가 정의 고정(국채선물 15:45 마감 기준, KOSPI200은 15:30 현물 마감 기준인지 여부 확인) `[확인필요]`

## 7. 실험 버전

- **V0 (시험 운영, ~20일):** 파이프라인 검증만. 성능 결론 없음.
- **V1:** 프롬프트 고정, 다올 + 유진 + 미국 지수 + T 스냅샷. 150일 목표(소급 포함 가능 시 단축).
- **V2:** 요인을 하나씩 추가(경제지표 일정 / 외국인 국채선물 수급 / 오전 변동성 / 과거 유사 사례 / 앙상블 / 확신도 기준). 동일 기간에서 V1과 쌍비교.

## 8. 진행 순서

1. ✅ 기획 정리 (이 문서) → 사용자 확정
2. 리포트 입수 시각 5거래일 로깅 → T=10:00 적정성 점검 (`late` 비율 확인)
3. ✅ 일별 입력·예측·정답 양식 설계 → `03_데이터구조.md`, `06_코드/schemas/`
4. ✅ AI 출력 JSON 스키마 (v0.1, 틱 크기·중립 구간 미확정)
5. ◑ PDF 직접 입력 방식 검증 → `04_PDF읽기_검증.md` (1일치 완료, 3일치 목표 미달)
6. ✅ 격리 실행 구조 작성 → `05_실행구조.md`, `06_코드/run_prediction.py` (가짜 스냅샷 dry-run 통과, 정식 실행은 neutral_band 확정 후)
7. 하루치 테스트 → V0 시험 운영
8. V1 평가 → V2 개선
9. 실거래 가능성 검토 (비용·체결·규제 포함, 현재 범위 밖)
