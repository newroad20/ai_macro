## 3. ① 문제 정의

**업무 상황**
- 운용 조직은 매일 아침 증권사·IB의 매크로·채권 리포트와 전날 밤 해외 시장, 중앙은행 이벤트(FOMC·금통위)를 읽고 하우스뷰와 회의 자료를 만든다.
- 이 해석이 자산배분(SAA/TAA) 논의의 입력이 된다.

**현행 방식의 문제**
1. **읽고 대조하는 데 시간이 많이 든다.** 리포트마다 같은 지표의 값이 조금씩 다르다.
   - 실측(2026-11-09): 두 증권사의 국고 3년이 3.615% vs 3.613%
   - 실측(2026-11-05): 10년 선물 1주 변화가 105틱 vs 145틱
2. **이미 가격에 반영된 정보와 새 정보를 구분하기 어렵다.** 리포트는 대부분 전일 마감 기준인데, 실제 판단은 장중에 내린다.
3. **해석이 맞았는지 검증하지 않는다.** 중장기 뷰는 맞았는지 판명되기까지 수년이 걸려, 해석 능력에 대한 피드백 고리가 없다.
4. **범용 LLM 요약을 그대로 쓰기 어렵다.**
   - 표의 수치를 잘못 읽는다. 실측: 국고10Y −5.0bp를 바로 아래 20Y 행의 −4.0bp로 기재했다.
   - 출처가 불분명하다.
   - 애널리스트 의견을 되풀이하는지 스스로 판단했는지 알 수 없다.

**주요 사용자 / 시나리오**
- 사용자: 해외채권·멀티에셋 운용역, 매크로 리서치 담당, 투자위원회
- 시나리오: FOMC 다음 날 08:30, Agent가 발표문과 리포트를 읽고 자산군별 반응 메모를 만든다 → 09:00 회의에서 검토 → 장 마감 후 Agent가 스스로 채점하고 다음 날 아침 메모에 결과를 함께 보고한다.

**해결 필요성**
- AI를 리서치에 쓰려면 "AI의 매크로 해석이 신뢰할 만한가"를 **측정할 수 있어야** 한다.
- 단기 시장 반응은 며칠 안에 정답이 나온다. 그래서 해석 능력을 반복적으로 채점할 수 있는 가장 빠른 시험대가 된다.

## 4. ② 서비스 제안 및 차별성

**개요**
- MacroProof는 "리서치를 대신 읽어주는 AI"가 아니다.
- 판단을 기록하고 스스로 채점받는 **검증 가능한 리서치 Agent**다.

**흐름 (입력 → 수행 → 결과물)**
```
[입력] 리포트 PDF · 중앙은행 발표문/기자회견 · 기준 시각 시장 스냅샷
  → ① 수집·독해: 시점 확인(생성·입수 시각), 원문 PDF 직접 독해, 리포트 간 수치 교차검증
  → ② 해석: 컨센서스 대비 서프라이즈, 이미 반영된 요인과 남은 재료 구분
  → ③ 뷰 메모: 자산군별 방향·확률·확신도 + 근거(출처 명시) + 무효화 조건
  → (시장 마감/1일/1주 후)
  → ④ 수치 평가: 적중·획득 틱을 기준선과 비교
  → ⑤ 근거 채점: 별도 Agent가 원문 대조, 결과론 배제 채점, 일반화 교훈 생성
[결과물] 아침 메모 · 사후 채점표 · 누적 트랙레코드 · 개선 제안(사람 승인 후 반영)
```

**차별점**
1. **시점 통제(누수 차단)**
   - 기준 시각 이후 자료는 입력하지 않는다.
   - 정답은 격리된 폴더에 두고, 예측은 저장 후 수정할 수 없게 한다.
   - 입력 패키지는 해시로 기록한다.
2. **근거를 행 단위로 검증**
   - 채점 Agent가 PDF 표의 행·열까지 대조한다.
   - 실측: 사람이 찾았던 오독을 채점 Agent가 위치까지 지적했다.
3. **애널리스트 추종 기준선**
   - "리포트 전망을 그대로 따른 결과"와 비교해 AI 고유의 부가가치만 측정한다.
4. **결과론을 배제한 채점과 학습 루프**
   - "맞혔지만 근거가 틀림"과 "틀렸지만 합리적"을 구분한다.
   - 교훈은 일반화된 문장으로만 축적한다(정답 암기 금지).

## 5. ③ Agent 역할 및 Workflow

| Agent | 목표 | 자율 수행 | 종료 조건 |
|---|---|---|---|
| ① 수집·독해 | 기준 시각까지 확보된 자료 패키지 구성 | 생성·입수 시각 판정, 지연 자료 분리, 입력 해시 기록 | 필수 자료가 기준 시각 내에 있음. 없으면 late로 분리 |
| ② 해석 | 이벤트·리포트의 서프라이즈와 반영 정도 판단 | 문서 검색(RAG), 리포트 간 불일치 표시 | 근거 항목마다 출처 존재 |
| ③ 뷰 메모 | 자산군별 반응 가설 작성 | 방향·확률·확신도, 무효화 조건 | 스키마 검증과 의미 검증 통과(확률 합 1, 방향-확률 일치 등). 실패 시 저장하지 않음, **자동 재시도 금지**(유리한 결과만 고르는 것 방지) |
| ④ 수치 평가 | 결과 대비 성과 측정 | 기준선 계산, 확신도별 집계 | 정답 기록 시각이 예측 이후임을 확인 |
| ⑤ 근거 채점 | 판단의 질 평가와 교훈 도출 | 원문 대조, 무효화 조건 판정, 추론 분류 | 스키마 통과, 교훈은 일반화 문장 |

- **사람의 역할**: 프롬프트·요인 변경 승인(버전 관리), 최종 투자 판단. Agent는 매매하지 않는다.
- **개선 루프**: 교훈 누적 → 사람 검토 → 새 버전 → 같은 기간에서 이전 버전과 쌍비교 (한 번에 한 요소씩)

## 6. ④ AI 기술·Tool/API 구성

- **모델**
  - 예측: Claude Sonnet 5.5
  - 채점: Claude Opus 5 (예측과 다른 모델을 써서 자기 선호 편향 완화)
  - 모델 ID와 프롬프트 버전을 매 실행 기록한다.
- **Agent 실행 환경**: Claude Code 비대화형 실행
  - 전역 설정·메모리·플러그인 차단
  - 도구는 Read만 허용, 프로젝트 밖 임시 폴더에서 실행
  - 실측: 정답 폴더와 전역 설정 읽기가 거부됨을 확인
- **구조화 출력**: JSON 스키마 강제 → 실행기가 스키마와 의미 규칙을 다시 검증
- **RAG**: 한은 통화정책 문서를 Pinecone 벡터 DB에 적재(Gemini embedding)해 발언 해석 근거로 검색 (n8n 워크플로 구현). 본선에서는 Fed 문서까지 확장.
- **Memory**
  - 트랙레코드 DB (예측, 평가, 채점)
  - 교훈 저장소: 사람이 승인한 교훈만 다음 버전에 반영
  - 예측 세션은 과거 정답을 보지 않는다.
- **Tool/API**

| 도구 | 역할 | 호출 조건 |
|---|---|---|
| PDF Reader | 리포트 원문 독해 | 표 깨짐을 피하려 텍스트 추출 대신 원본 직접 입력 |
| 시장 데이터 (KRX, 한은 ECOS, FRED) | 스냅샷과 정답 | `[확인]` API 접근 범위 |
| 스키마 검증기 | 출력 검증 | 매 실행 |
| 평가기 | 기준선 비교 | 정답 기록 후 |
| 채점 Agent | 근거 검증 | 평가 후 |

- **신뢰성 확보**
  - 근거마다 출처 필드 필수
  - 수치 오독은 채점 Agent가 원문과 대조
  - 이상치 입력 차단(전일 대비 한도)
  - 덮어쓰기 금지, 실패는 로그만 남김
  - 비용·시간 로깅

## 8. ⑥ MVP 개발 계획

**현재 구현 상태 (예선 시점)**
- 일간 모드 전체 파이프라인: 기록 → 격리 예측 → 수치 평가 → 근거 채점 (Python, 시험 실행 완료)
- 금통위 기자회견 반응 예측 데모, n8n RAG 챗봇

**MVP 범위 (본선)**
1. 이벤트 모드: FOMC·금통위 발표문 입력 → 자산군(미국채 2·10년, 국고 3·10년, USD/KRW, 주가지수) 반응 메모 → 1일 후 자동 채점
2. 일간 모드 정식 운영과 소급 표본 확대
3. 대시보드: 트랙레코드, 기준선 대비 성과, 확신도별 적중, 근거 오류율, 교훈 목록

**기술 스택**: Python, Claude(Anthropic), Claude Code CLI, n8n, Pinecone, Streamlit `[가정]`

**일정** `[확인: 본선 기간]`
- 1주차: 이벤트 모드 스키마·프롬프트, 데이터 수집기
- 2주차: 소급 검증 실행, 대시보드
- 3주차: 통합 데모, 성능 보고

**완료 기준**: 이벤트 1건 입력부터 메모와 채점까지 사람 개입 없이 완료, 소급 표본 결과 보고

**데모 시나리오**: 최근 FOMC 발표문 업로드 → 약 1분 내 메모 → 다음 날 실제 시장으로 채점 → 대시보드에 누적

**리스크와 대응**

| 리스크 | 대응 |
|---|---|
| 표본이 작아 성능 결론이 어려움 | 시험 운영과 성능 평가를 분리, 소급 검증, 주 지표 사전 고정 |
| 리포트 저작권 | 원문 비공개, 해시와 인용 최소화 |
| 장중 데이터 접근 | 종가 기준 이벤트 모드 우선 |
| LLM 확률 보정 문제 | 확률은 기록만 하고 판단은 확신도 3단계로 |
| 비용 | 실행당 비용 로깅 |

## 9. ⑦ 기대효과 및 확장성

**시간**
- 리포트 2종 + 시장 스냅샷 메모 생성: 약 25~45초, 실행당 약 $0.2 (구독 사용량 기준 표시값, 실측)
- 근거 채점: 약 90초, 약 $0.4 (실측)
- 사람이 하던 아침 정리 시간 `[가정: 설문·인터뷰로 보완]`

**품질**: 수치 오독과 리포트 간 불일치를 자동으로 검출하고, "이미 반영"과 "남은 재료"를 명시적으로 구분

**신뢰성**: 모든 판단에 시점, 입력 해시, 모델·프롬프트 버전이 남는 **감사 가능한 리서치 이력**

**확장**
- 자산: 국내 채권 → 미국채·Bund·달러·글로벌 주식
- 기간: 장중 → 1일 → 1주 → TAA 시그널 연구
