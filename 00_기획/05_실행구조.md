# 예측 실행 구조 (단계 6, v0.1)

코드: `06_코드/run_prediction.py` · 프롬프트: `06_코드/prompts/predictor_v1.0.md` · 설정: `06_코드/experiment_config.json`

## 실행 방법

```text
# 정식 (T 시각에 스냅샷을 기록한 뒤)
python 06_코드/run_prediction.py 2026-11-06

# 시험 (결과는 99_로그/dryrun 에만 저장)
python 06_코드/run_prediction.py 2026-11-05 --dry-run --snapshot dryrun/2026-11-05.snapshot.json
```

필요 파일: `02_시장데이터/스냅샷/B/<날짜>.json`, `01_리서치_원본/<날짜>/`에 스냅샷 `reports[].file`과 같은 이름의 PDF 2개.

## 하루 운영 (가장 간단한 방식)

시트나 폼 없이, **Claude Code에게 숫자를 말로 알려주면** 아래 명령을 실행한다 (직접 실행도 가능).

```text
10:00  "스냅샷: 3년선물 103.62, 10년선물 108.71, 코스피200 395.12, 환율 1339.8, S&P +0.41, 나스닥 +0.62"
       → python 06_코드/record.py snapshot <날짜> --f3 … --f10 … --k200 … --fx … --spx … --ndx …
       → python 06_코드/run_prediction.py <날짜>

15:45~ "마감: 3년 103.90, 10년 108.95, 코스피200 396.40, 환율 1337.5"
       → python 06_코드/record.py answer <날짜> --f3 … --f10 … --k200 … --fx …
```

- **입력은 스냅샷 6개, 정답 4개.** 리포트 PDF는 `01_리서치_원본/<날짜>/`에 넣어 두기만 하면 된다.
- 자동으로 채움: 기준 시각(설정의 T), 기록 시각(지금), 리포트 생성·입수 시각(PDF), 전일 종가(직전 정답 파일), 미국 세션 날짜(직전 평일).
- 첫날은 직전 정답이 없으므로 `--prev-f3 --prev-f10 --prev-k200 --prev-fx`로 전일 종가를 준다. 미국 휴장일 다음 날은 `--us-date`로 지정한다.
- 막는 것: 거래일 당일이 아닌 정식 기록, 덮어쓰기, 전일 대비 이상치(선물 1~1.5%, KOSPI200 6%, 환율 2.5%, 미국 지수 8% 초과), 예측 전 정답 기록, 15:45 이전 정답 기록, 입력 누락. 연습은 `--dry-run`, 검사 무시는 `--force`.
- 미국 지수는 **등락률만** 받는다 (종가 수치는 스키마상 선택 항목).
- 시험: 임시 폴더로 10개 시나리오(정상·이상치·덮어쓰기·날짜·예측 전 정답·장 마감 전·누락 등) 통과.

## 흐름

```text
스냅샷 검증(스키마) → late 판정 → 입력 패키지 생성(스냅샷+PDF+MANIFEST 해시)
→ 프로젝트 밖 임시 폴더에서 claude -p 실행 → 스키마+의미 검증 → 04_예측결과/B/<날짜>.json 저장
→ 요약은 99_로그/runs.log.jsonl, 원본 전체 로그는 99_로그/runs/
```

실행기가 쓰는 Claude 옵션: `--safe-mode`(CLAUDE.md·플러그인·훅·메모리·MCP 차단), `--no-session-persistence`, `--tools Read`(읽기만), `--model <고정>`, `--system-prompt`(버전된 프롬프트), `--json-schema`(출력 형식). 구독 인증을 쓰므로 `--bare`(API 키 전용)는 사용하지 않는다.

## 격리 확인 결과 (claude 2.1.201, 실측)

| 확인 | 결과 |
|---|---|
| 전역 CLAUDE.md·OMC 지침이 로드되는가 | 아니오 (모델 자체 답변 NO, 입력 토큰도 약 5천) |
| 프로젝트 파일(정답 폴더 포함) 읽기 | **거부** ("권한 미부여") |
| 전역 `~/.claude/CLAUDE.md` 읽기 | **거부** |
| 실제 시험 실행에서 읽은 파일 | 임시 폴더의 snapshot.json, PDF 2개뿐 |

- 근거는 작업 폴더 밖 읽기가 비대화형 모드에서 권한 거부되는 동작이다. **CLI 버전이 바뀌면 같은 확인을 다시 한다.**
- 로그를 보면 도구는 `Read`와 출력용 `StructuredOutput`만 사용했다.

## 실행기가 막는 것

- 같은 날짜의 예측 파일이 이미 있으면 거부(덮어쓰기 금지, 자동 재시도 없음). 검증 실패 시 저장하지 않고 로그에만 남긴다.
- `neutral_band_ticks`가 null이면 정식 실행 거부 → 중립 구간을 **사전에 고정**하게 강제.
- 정답 파일이 이미 있으면 정식 실행 거부.
- late(스냅샷 지연, 또는 리포트 생성·입수 시각이 T 이후)이면 `--allow-late` 없이는 거부, 허용 시 `04_예측결과/B/late/`로 분리 저장.
- 확률 합계, direction=확률 최대, duration_view 일치, 틱 부호 일치, 중립일 때 틱 범위를 검사한다.

## 시험 실행(dry-run) 결과 — 2026-11-05 PDF, 가짜 스냅샷

- 처음부터 끝까지 정상 완료, 약 23초, 표시 비용 $0.19(구독 사용량 기준 참고값), 출력 토큰 3,228개.
- 모델 ID는 `claude-sonnet-5-5`로 기록됨. 별칭이 아닌 전체 이름으로 고정했다.
- 모델은 스냅샷의 가짜 값(T값=전일 종가, 미국 지수 0)을 스스로 알아채 신뢰도를 low로 내렸고, 두 리포트의 불일치(1주 변화 105 vs 145틱, 국고 10년 3.950 vs 3.968)도 근거에 반영했다. 지침이 작동한다는 증거다.
- 실행 중 `StructuredOutput` 호출이 JSON 파싱 오류로 두 번 실패한 뒤 세 번째에 성공했다. 세션 내부 재시도로 최종 결과는 하나이며 영향은 비용뿐이다. 빈도는 운영하며 관찰한다.

## 발견된 문제

1. **근거 수치 오독 1건.** 모델이 "국고 10년 3.950%(−4.0bp)"라고 적었으나 다올 원본은 −5.0bp이다(−4.0은 바로 아래 20년물). 텍스트 일치 검사로는 −4.0이 PDF 어딘가에 존재해 걸러지지 않는다.
   - 대응: 평가 단계의 **LLM 근거 평가에 "근거 수치 충실도"** 항목을 넣고, 판정 세션이 PDF를 직접 열어 인용 수치를 대조하게 한다. 예측 점수와 별도로 오독률을 집계한다.
2. 프롬프트 v1.0의 `invalidation_conditions` 문장 일부가 어색하다(예: 「±3틱을 넘어 마감 (상승 시 롱, 하락 시 숏이 맞았음)」). 의미는 통하나, 평가에 쓰려면 "관측 가능한 조건 + 임계값 + 방향" 형식을 요구하도록 v1.1에서 다듬을지 정해야 한다. 정식 운영 전에만 바꾼다.
