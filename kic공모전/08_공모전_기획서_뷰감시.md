## 3. ① 문제 정의

**업무 상황**
- 해외 자산 운용 조직은 금리·환율·경기에 대한 뷰를 세우고, 이것이 자산배분(SAA/TAA) 논의의 전제가 된다.
- 뷰는 몇 주에서 몇 달 동안 유지되며, 그 사이 매일 새로운 발언과 지표가 나온다.

**현행 방식의 문제**
1. **뷰를 세운 뒤 감시하지 못한다.** 어떤 일이 생기면 뷰를 접을지 미리 적어두지 않거나, 적어도 매일 확인하지 않는다.
2. **읽을 자료가 너무 많다.**
   - 실측(2026-11-10): 주요 매체 5곳에서 하루 136건을 수집했고, 그중 채권 운용과 관련이 높은 기사는 15건이었다. `[확인: 매체 수]`
3. **뷰가 틀렸을 때 돌아보지 않는다.** 판명까지 시간이 걸려, 근거가 틀렸는지 운이 나빴는지 구분하지 않고 넘어간다.
4. **감시를 AI에 맡기려면 판정 근거를 원문과 대조해야 한다.**
   - AI가 수치를 잘못 읽는다. 실측: 범용 LLM 요약이 표에서 국고10Y −5.0bp를 바로 아래 20Y 행의 −4.0bp로 기재했다.
   - 자료끼리도 수치가 다르다. 실측(2026-11-05): 같은 지표를 두 리포트가 105틱과 145틱으로 적었다.

**주요 사용자 / 시나리오**
- 사용자: 해외채권·멀티에셋 운용역, 매크로 리서치 담당, 투자위원회
- 시나리오
  1. 운용역이 뷰를 등록한다. "Fed는 12월에 인상한다. 미국채 2년 금리가 4.40% 아래에서 3거래일 연속 마감하면 무효." `[확인: 조건 값은 예시. 직접 정할 것]`
  2. 매일 아침 Agent가 자료를 수집해 뷰별 상태를 보고한다. "유지. 강화 근거 2건, 약화 근거 1건."
  3. 무효화 조건에 닿으면 원문 위치와 함께 알린다. 뷰를 접을지는 운용역이 정한다.
  4. 뷰가 끝나면 Agent가 근거와 결과를 채점하고 교훈을 남긴다.

**해결 필요성**
- 뷰가 틀리는 것은 피할 수 없다. 문제는 틀린 줄 모르고 유지하는 것과, 틀린 뒤에 배우지 않는 것이다.

## 4. ② 서비스 제안 및 차별성

**개요**
- 사용자는 뷰를 등록하기만 한다. 무엇을 찾아 읽고, 어느 자료가 뷰와 관련 있는지, 언제 알릴지는 Agent가 정한다.
- MacroProof는 예측을 대신하는 AI가 아니라 **사람의 판단을 지켜보고 검증하는 Agent**다.

**흐름**
```
[입력] 뷰(자유 서술)
  → ① 구조화: 뷰 카드 작성. 조건이 측정 불가하면 되묻는다
  ── 매일 ──
  → ② 수집 [탐색]: 뷰별 검색 계획 → 자료·지표 수집 → 선별 → 패키지 확정
  → ③ 판정 [봉인]: 패키지만 읽고 강화/약화 판정, 무효화 조건 저촉 여부
  → ④ 검증 [탐색]: 판정의 수치·인용을 원문과 대조. 불일치면 반려
  ── 뷰 종료 시 ──
  → ⑤ 결산: 결과 판정(코드) + 근거 타당성 채점 + 교훈
[결과물] 일일 뷰 상태 보고 · 무효화 알림 · 결산표 · 누적 성적
```

**뷰 카드와 일일 판정** `[확인: 수작업으로 구성한 예시. 마감 전 실제 실행 결과로 교체하고 "실행 결과"로 표기]`

| 뷰 카드 | |
|---|---|
| 주장 | Fed는 12월 FOMC에서 정책금리를 인상한다 |
| 결과 판정 기준 | 12월 FOMC 결정문의 목표범위 상향 여부 |
| 무효화 조건 | ① 미국채 2년 금리가 4.40% 아래에서 3거래일 연속 마감 ② 12월 FOMC 전 발표되는 근원 CPI 전월비가 `[입력]`% 미만 `[확인: 값은 예시]` |
| 시장 함의 (채점 제외) | 미국채 2년 금리 상승 |

| 일일 판정 (2026-11-10) | |
|---|---|
| 상태 | 유지 (조건 ① 미저촉: 2년 4.54% 내외) |
| 강화 | Goolsbee: 물가 책무 달성 실패 언급 / Barkin: 방향은 분명, 속도는 신중 (2026년 투표권 없음) `[확인: 발언 날짜]` |
| 약화 | NY Fed 조사: 실업 전망 2020년 이후 최악 |
| 예정 | 오늘 10월 CPI 발표. 12개월 상승률은 미공표이나 조건 ②는 전월비 기준이라 확인 가능 |
| 검증 | `[입력: 실제 검증 결과. 인용 n건 중 n건 원문 일치]` |

**차별점**
1. **예측이 아니라 감시**: AI가 뷰를 대신 세우지 않는다. 사람의 뷰를 조건에 비추어 매일 점검한다.
2. **판정 근거의 원문 검증**: 별도 Agent가 판정에 쓰인 수치와 인용을 원문의 해당 위치와 대조한다. 실측: 사람이 찾았던 표 오독을 Agent가 위치까지 지적했다.
3. **시점 통제**: 뷰 카드는 등록 후 고칠 수 없고 수정은 새 버전으로 남는다. 판정에는 그 시각까지의 자료만 쓴다.
4. **결과론을 배제한 결산**: "맞혔지만 근거가 틀림"과 "틀렸지만 합리적"을 구분하고, 공개 기준선(현 상태 유지, 등록 시점의 공식 전망)을 그대로 따랐을 때와 비교한다.

## 5. ③ Agent 역할 및 Workflow

**설계 원칙**: 자료를 찾고 검증하는 단계는 도구를 넓게 주고(탐색), 뷰 상태를 판정하는 단계는 넘겨받은 패키지만 읽게 한다(봉인). 판정이 무엇에 근거했는지 재현할 수 있다.

| Agent | 목표 | 작업 계획 | 스스로 판단·수행 | 종료 조건 |
|---|---|---|---|---|
| ① 구조화 | 뷰를 검증 가능한 형태로 고정 | 주장에서 결과 기준·기간·조건 추출 | 무효화 조건이 측정 가능한지 판단, 불가하면 사용자에게 질문 | 뷰 카드 스키마 통과, 사용자 확인 |
| ② 수집 (탐색) | 뷰별 당일 패키지 확정 | 뷰별 검색어와 조회할 지표 목록 작성 | 자료 수집·선별, 제목·본문 불일치 자료 제외, **무효화 조건에 필요한 지표 스냅샷 조회**, 부족하면 추가 검색 | 패키지(자료+지표 스냅샷) 확정. 없으면 "해당 없음" 기록 |
| ③ 판정 (봉인) | 뷰 상태 갱신 | 자료를 근거 항목에 대응 | 강화/약화/무관 분류, 스냅샷으로 무효화 조건 저촉 판단, 상태(유지/주의/무효화 후보) 결정 | 판정마다 출처 문장 존재, 스키마 통과 |
| ④ 검증 (탐색) | 판정 근거의 정확성 확인 | 수치·인용 주장을 나열하고 주장별 확인 방법 결정 | 원문 대조, 지표 재조회, 확인이 안 되면 추가 탐색, 불일치 시 판정 반려 | 모든 주장이 확인/불일치/확인 불가로 판정됨. 또는 호출 한도 `[입력: 회]` 도달 |
| ⑤ 결산 | 종료된 뷰의 복기 | 뷰 이력을 시간순으로 재구성 | 근거 타당성 평가, 공개 기준선과 비교, 알림이 시장보다 앞섰는지 확인, 교훈 작성 | 스키마 통과, 교훈은 일반화 문장 |

- **사람의 역할**: 뷰의 등록·수정·종료, 무효화 확정, 교훈 반영 승인, 투자 판단. Agent는 "무효화 후보"까지만 알리고 매매하지 않는다.
- **구현 구분**
  - 현재 구현: ② 수집·선별·주제 추적, ④ 원문 대조 검증, ⑤ 수치 평가와 근거 채점 `[확인: 수집기와 채점 파이프라인은 현재 별도 프로그램]`
  - 예선 시점 시험: 뷰 카드 1건의 하루치 판정·검증 `[확인: 실행했으면 유지, 못 했으면 삭제]`
  - 본선 구현: ① 구조화, ③ 판정의 정식 구현, 무효화 알림, 두 프로그램의 통합
- **예외 처리**: 실패 시 저장하지 않고 원본 로그를 보존한 뒤 사람에게 알린다. 형식 오류에 한해 1회 재시도하고 모든 시도를 기록한다. 기존 시험 운영에서는 재시도를 금지했으나, 판정 시점에는 결과가 정해지지 않아 재시도로 유리한 답을 고를 수 없으므로 형식 오류에 한해 허용한다. 내용 검증 실패는 재시도하지 않는다.

## 6. ④ AI 기술·Tool/API 구성

- **모델**: 판정 Claude Sonnet 5.5, 검증·결산 Claude Opus 5. 판정과 검증을 다른 모델로 분리했다. 같은 회사 모델이라 편향이 완전히 제거되지는 않으며, 본선에서 타사 모델 검증과 비교한다. 모델 ID와 프롬프트 버전을 매 실행 기록한다.
- **Agent Framework**: Python 실행기가 단계를 넘기고, 각 Agent는 Claude Code 비대화형 실행으로 돈다. Agent별로 허용 도구를 다르게 준다.
- **실행 환경**: 전역 설정·메모리·플러그인 차단, 프로젝트 밖 임시 폴더. 실측: 봉인 세션에서 허용되지 않은 폴더와 전역 설정 읽기가 거부됨을 확인했다.
- **구조화 출력**: 뷰 카드·판정·결산 모두 JSON 스키마 강제 → 실행기가 스키마와 의미 규칙을 다시 검증한다.
- **RAG**: 한국은행 통화정책 문서를 Pinecone에 적재했다(Gemini embedding, n8n 워크플로). 본선에서 Fed 문서를 추가해, 발언이 과거 입장과 달라졌는지 판단하는 근거로 쓴다.
- **Memory**: 뷰 이력 DB(카드 버전, 일일 판정, 알림, 결산)와 교훈 저장소. 사람이 승인한 교훈만 반영한다.

**Agent별 도구 권한**

| 도구 | 입력 → 출력 | ②수집 | ③판정 | ④검증 | 호출 조건 |
|---|---|---|---|---|---|
| 자료 수집기 | 검색어·기간 → 제목·링크·본문 | ○ | ✕ | ○ | 매일, 추가 탐색 시 |
| 문서 Reader | 파일 → 본문·표 | ○ | ○ (패키지만) | ○ | 매 실행 |
| 시장·지표 조회 | 지표·날짜 → 발표 시점 값 | ○ | ✕ (②가 넘긴 스냅샷 사용) | ○ | 무효화 조건 확인, 수치 재확인 `[확인: API 접근 범위]` |
| 문서 검색(RAG) | 질의 → 관련 문단과 출처 | ○ | ✕ | ○ | 과거 발언과 비교할 때 |

**실행기가 호출하는 도구**: 스키마 검증기(매 실행), 평가기(뷰 종료 후 결과 판정), 알림 발송(상태가 무효화 후보로 바뀔 때)

**신뢰성 확보**
- 판정마다 출처 문장 필수, 검증 Agent가 원문과 대조해 불일치면 반려
- 조회 기준일을 판정 시각 이전으로 제한, 지표는 발표 시점 값 사용
- 뷰 카드와 판정은 덮어쓰지 않고 버전으로 기록
- Agent별 도구 호출 한도와 비용 한도, 초과 시 중단하고 기록

| 중앙은행 자료 | Fed·ECB·BOJ·한국은행 발표문, 연설, 의사록 | 매일 `[입력: 수집일]` | `[확인]` | 발언 단위 분할, 뷰 근거 판정, RAG 적재 |
| 경제지표 | BLS, ALFRED(발표 시점 값 보관), 한국은행 ECOS | 발표 시 `[입력]` | `[확인]` | 무효화 조건 확인, 수치 검증. 사후 수정된 값이 아닌 당시 값 사용 |

- **본선 데모 입력**: 누구나 재현할 수 있도록 중앙은행 자료와 공개 지표·시장 데이터를 기본으로 한다.
- **시점 통제**: 자료마다 공개 시각을 기록하고, 판정에는 그 시각까지의 자료만 쓴다.
- **결산 기준선 (모두 공개 자료)**
  - 현 상태 유지: 등록 시점의 상태가 바뀌지 않는다고 본 경우(예: Fed 동결)
  - 공식 전망: 등록 시점에 공개된 최신 SEP 점도표 중앙값 등. 지표형 뷰는 SPF 중앙값
  - 시장 내재 확률(금리 선물 기준)은 데이터 이용 조건을 확인한 뒤 본선에서 추가 검토 `[확인]`
- **과거 재생과 표본**
  - 재생 자료는 날짜가 고정된 중앙은행 자료와 ALFRED의 발표 시점 값으로 한정한다. 뉴스는 과거 날짜를 다시 수집하기 어려워, 수집기가 이미 쌓아 둔 `[입력: 시작일]` 이후분만 쓴다.
  - 사용 모델의 학습 시점 이후 기간만 재생한다(모델이 결과를 기억할 가능성 차단). 그래서 재생 가능한 기간은 `[입력: 개월]`개월, 뷰 `[입력: 건]`건 안팎이다.
  - 표본이 작으므로 성과 결론은 내지 않고, 인용 정확도와 알림 타당성을 주 지표로 보고한다.

## 9. ⑦ 기대효과 및 확장성

| 구분 | 기존 | MacroProof |
|---|---|---|
| 뷰 감시 | 담당자가 기억하는 범위에서 수시로 | 매일, 등록된 조건 기준으로 |
| 자료 선별 | 사람이 직접 훑음 `[입력: 소요 시간과 근거]` | 하루 백여 건에서 뷰 관련 자료만 선별 `[입력: 실측 소요 시간]` |
| 근거 수치 확인 | 사람이 발견할 때만 | 매 판정 원문 대조 |
| 뷰의 복기 | 하지 않거나 비정형 | 종료 시마다 근거와 결과를 분리해 채점, 공개 기준선과 비교 |
| 판단 이력 | 흩어져 있음 | 카드 버전, 일일 판정, 입력 해시, 모델·프롬프트 버전 |

**실측 시간·비용 (기존 파이프라인, 구독 사용량 기준 표시값)**
- 해석 메모 생성(Sonnet 5.5): 중앙값 18초, 약 $0.14 (n=7, 10~43초, $0.10~0.26)
- 근거 검증(Opus 5, 결과를 보지 않고 원문 대조): 중앙값 73초, 약 $0.32 (n=4, 65~94초, $0.28~0.45)

**확장**
- AI 섀도 뷰: 기존 일간 예측 파이프라인을 뷰 카드 양식으로 전환해, AI의 뷰도 같은 틀로 결산한다.
- 외부 리서치의 뷰까지 같은 틀로 결산해 사람·AI·리서치의 해석을 비교한다.
- 자산: 금리·환율 → 주식·크레딧 / 기간: 이벤트 단위 뷰 → 분기 단위 TAA 뷰

**운영 적용 경로**: 개인 뷰 감시(섀도 모드) → 팀 회의 자료 → 위원회의 뷰 이력 관리. 투자 판단과 매매는 사람이 한다.
